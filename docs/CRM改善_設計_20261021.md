## 1. 先に直す既存のバグ（設計で見つかったもの・2体が独立に指摘）

1. **出荷の下書きを削除すると、引いていない在庫が戻る**（在庫が水増しされる）
   - `deleteShipment`（supply.js:1641-1653）が状態を見ずに `shipUsedStock(s)` で戻している。Web申込の下書きは `fulfillment` 無し＝在庫扱い（index.js:1044-1060・supply.js:1639）。
2. **下書きの数量を直すと在庫が動き、確定のときにもう一度全量を引く**（二重引き落とし）
   - `saveShipEdit`（supply.js:1516, 1555, 1567）が `shipUsedStock` だけで差分を動かす。確定（988-991）で全量を引く。
3. **「発送済にする」を2人が同時に押すと二重に引かれる**（confirmDraftShipment が tx を使っていない 984-991）。
4. **申込（acceptQuote）が出荷の既存を確かめない**ので、別の版の見積もりがもう一度申し込まれると下書きが2つできる（清珠会 #255〜257 の重複の推定原因）。`createOrUpdateMitsumoriQuote`（594-596）が `issued` だけを superseded にし、accepted の旧版が残るため。
5. **申込が案件の状態を無条件に 3 へ戻す**（1069-1072）。進んだ案件（5 以上）でも 3 に戻ってしまう。
6. **日次まとめの申請期限が 2027-03-12 固定**で設定（subsidyDeadline）が効かない／**対象外（archived）を除外していない**（画面と食い違う）。

→ 判定の正本を新しい純粋関数 `stockDeducted(s)`（状態が shipped/invoiced/paid かつ fulfillment≠direct）にし、**在庫を戻す・差分を動かすのはこれが真のときだけ**にする。1〜3 は S、4〜5 は A、6 は N で直す。
→ 過去の削除で在庫が水増しされていないかは、inventoryMovements の `shipment_canceled` のうち対応する引き落としが無い soNumber を数えれば分かる（**調べるだけ**・実装後に1回）。

### N1 担当が決まったら本人に通知
- Chat ID: `users/{email}.chatUserId`（数字のみ）。利用者管理（users.js/users.html）で管理者が入力。一覧に「Chat通知: 設定済／未設定」。**既知のIDは chat_write.py の `who` で取れる**（23人分取得済み）。
- 検知: **Firestore トリガー `onCaseAssigned`（onDocumentUpdated cases/{id}）**。条件 before≠after の assignedUserId・空でない・archived でない・統合ではない。画面の saveAssignee は `assignedBy`・`assignedAt` を追加で書く。自分で自分を担当にしたときはメンションしない。担当を外したときは投稿しない。
- 二重防止: `_notifyLog/assign_${event.id}` を create（既にあれば何もしない）。トリガーは cases に書かない（ループしない）。活動の記録は画面側が既にしているので追加しない。

### N2・N3 日次まとめ
- 全体1通: 期限（設定値）／**初期連絡の超過（5営業日超・状態1）**／未割当の新規（状態1）／**受注確定以降の未割当（画面と同じ定義）**／担当なしの停滞。
- **担当ごとに1通**（その人の未対応が1件以上のときだけ・@メンション）: 新規受信のまま（担当済み）／7日以上更新なし／入金待ち14日以上／期限間近／初期連絡の超過。
- 全項目で archived を除外。投稿の間に1.1秒。各節10件まで「…ほか N 件」。二重実行防止 `_notifyLog/daily_YYYY-MM-DD`。
- 管理者だけが使える `previewDailyFollowup`（投稿せず本文を返す）を作り、本番データで文面を確かめられるようにする。

### N4 承諾書の署名完了
- トリガー `onConsentSigned`（onDocumentUpdated consentRequests/{token}）。条件 pending→signed かつ method=web。紙の記録（新規作成）は対象外。
- 案件の活動に「承諾書にオンラインで署名されました」を記録し、Chat に投稿（担当を @メンション）。**確認者名は Chat に載せない**（CRMで見られる）。二重防止 `_notifyLog/consent_${token}`。
- **前提（デプロイ時に確認）**: トリガーの region を Firestore DB のロケーションに合わせる。fn-batch-sa に `roles/eventarc.eventReceiver`、初回は Eventarc／Pub/Sub のサービスエージェント権限。

## 5. A 電話・メールの申込を受注確定に

- `acceptQuoteTransaction` に `actor`（web／staff）を足して共用。スタッフ経路はトークン確認をしない。
- **共通の追加処理**: tx 内で案件の出荷を取得し、**生きている draft/requested があれば新しく作らず使い直す**（重複防止）。発送済以降があれば Web は作成を続けつつ `duplicateWarning` と Chat に注記、スタッフは拒否。
- 案件の状態は **1・2 のときだけ 3 にする**（5以上は据え置き、4・13 は拒否）。
- 新 Callable `staffAcceptQuote`（editor）: 入力 申込者名・受付方法（電話／メール／FAX／その他）・受付日・支払方法・確認メールの要否・同じグループの事業所。書く値 `orderedVia:"staff"`・`orderedAt`=受付日・`orderConfirmedBy`。見積には `acceptedVia/Channel/ReceivedDate/ByStaff`、`agreedPolicy:null`（同意を偽装しない）。
- 拒否条件は純粋関数 `functions/accept-rules.js` の `checkStaffAccept`（受理済み・旧版・期限切れ〔受付日で比較〕・受付日が未来・申込者名なし・失注/完了・キャンセル以外の出荷あり）。
- 画面: 見積カード（quote-admin.js）に「受注確定にする（電話・メールで申込を受けた）」（最新版で issued のときだけ）＋モーダル。

## 6. W 警告

- **完了(13)**: 純粋関数 `admin/js/case-complete-check.js` の `completionWarnings({shipments, subsidy})`。出荷なし／未発送／請求書未発行／入金未了（残額）／領収証未発行／申請日未入力／助成金の入金未記録／不採択 → 確認ダイアログ（止めない）。案件詳細とカンバンの両方。続行したら活動に「警告を確認のうえ完了: …」。`completedAt` を記録。
- **下書きの重複**: 純粋関数 `admin/js/ship-dup.js` の `findDuplicateDrafts`（案件ごとに draft/requested が2件以上・残す候補は cases.shipmentId）。供給管理のサマリーに「⚠ 下書きの重複 n件」、行に「重複」と「こちらを残す」（もう片方を理由「重複登録」でキャンセル＝**削除ではない**）。案件詳細の出荷タブにも帯。
- **在庫の目安**: `stockAdvice(items, products, locations)` で保管場所ごとに足りるかを下書きの行に1行（例「在庫: 滋賀 3/2台 ✓・東京 0/2台」）。

## 12. 実装後の変更点（レビュー・E2E を受けて・2026-10-21）

- §5 の「失注(4)・完了(13)は拒否」は**撤回**。Web・スタッフとも受け付けて案件を 3 に戻し、`reopenedFrom`・`reopenedAt` と活動「再申込で再開」を残す（戻ってきた事業所を画面のエラーで止めない）。
- 電話受注は、案件にすでに受注日（orderedAt）があれば上書きしない。キャンセル以外の出荷があれば拒否（先に整理）。
- 新しい版の見積への shipmentId の引き継ぎは**やめた**（申込時に案件の出荷を使い直すため不要。残すと未申込の版の改版で下書きが上書きされる）。
- Web 申込で出荷を使い直すときは申込の内容（届け先・明細・支払方法・希望日・伴走支援費の台数）を書き直し、状態・番号・出荷元は巻き戻さない。
- 請求前に全額入金した出荷は、請求済にしたとき入金済にする。発送済の行にも入金があれば「入金の履歴」を出す。返金していない入金がある出荷はキャンセル不可。
- 入金明細: 指紋に残高を入れない。同じ日付・金額・名義の明細が記録済みなら「取込済みの可能性」として自動選択せず、人が確認すれば `-2` 以降の ID で記録。CSV から記録した入金を取り消すと取り込み記録も消える。名義の先頭の「振込／ﾌﾘｺﾐ」は読み飛ばして振込人コードを拾う。
- 出荷指示: 依頼ごとに `requestSeq` を増やし、古い送信の結果で新しい依頼を上書きしない。送信中（ロック60秒以内）の依頼取り消しは止める。
- 日次まとめ: 途中で失敗し1件も投稿していなければ記録を消して再実行できるようにする。
- requireStaff の読み取り失敗は「権限の確認に失敗しました」の HttpsError にする。**aiAssist の fn-ai-sa に Firestore 読み取り権限の付与が必要**（デプロイ前）。
- E2E 用に `admin/js/emu.js`（localhost＋http＋?emu=1 のときだけエミュレーターにつなぐ。本番のホストでは動かないことを test-emu-guard で確認）。
- E2E で見つけた既存バグ: 案件詳細の重複候補が常に0件（未定義変数）／閲覧のみの人が供給管理の操作ボタン26個を押せた（保存はルールで拒否）→ 直した。
