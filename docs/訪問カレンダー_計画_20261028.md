# 訪問カレンダー（予定）画面 — 計画（2026-10-28・案）

## 1. ねらい
「今日、誰が・何時に・どこへ・何をしに行くか」を、CRM で1画面で確かめられるようにする。
ケアプー記録の「予定カレンダー」（`/schedule`）と同じ使い勝手にそろえ、両方を使う人が迷わないようにする。

## 2. 手本（ケアプー記録の予定カレンダー）の要点
| 項目 | ケアプー記録 |
|---|---|
| 作り | 自作（外部ライブラリなし）・表示専用。予定は事業所／記録の画面で入れる |
| 表示 | 月・週・日の切替（既定は月・今日）。前へ／次へ／今日。URL に `?view=&date=` |
| 1件の中身 | 時刻 → 担当者 → 事業所名（詳細へ）→ 住所（Googleマップ）→ Googleカレンダーに追加 → 種別・状態バッジ |
| 色 | 種別で色分け。対面／オンラインは色だけでなくアイコンでも区別 |
| 絞り込み | エリア（契約先）。担当者・「自分だけ」は無い |
| その他 | 担当者別の件数、60秒ごとの自動更新、JST 固定 |

## 3. CRM の現状（調査結果）
- 訪問の日付が3か所にある。
  - `cases.visitDate`（"YYYY-MM-DD"・時刻なし）＝案件詳細の「訪問予定日」。一覧・カンバンにも出ている
  - `supportChecklists/{caseId}.onsite`（当日タブ）＝ `visitDate`・`visitTimeFrom`/`visitTimeTo`（"HH:MM"）・`visitPlace`（office/online）。**時刻を持つのはここだけ**。案件の visitDate と同期していない
  - `sessions.sessionDate`＝実施した伴走支援の記録（予定ではない）
- 画面の追加は、`sidebar.js` の GROUPS に1行、雛形は `kanban.html`/`kanban.js`（認証 → `gateRole` → `applyViewerMode` → cases を全件 onSnapshot）。
- 練習モード: Firestore は必ず `/js/fs.js` 経由（`test-practice-mode.mjs` が全ページを検査）。
- カレンダー系ライブラリは入っていない。JST の共通関数（`todayYmdJst` など）はある。

## 4. 作るもの（第1段）
新しい画面 **「予定（訪問カレンダー）」** `admin/schedule.html` ＋ `admin/js/schedule.js`（サイドバー「案件」グループ、カンバンの下）。

| 項目 | 内容 |
|---|---|
| 既定の表示 | **今日の日ビュー**（今回の要望が「本日訪問する方の状況」のため。ケアプー記録は月が既定） |
| 切替 | 日・週・月（ケアプー記録と同じ並び・同じボタン位置）。URL に `?view=&date=` |
| 1件の中身（日ビュー） | 時刻（なければ「時刻未定」）／担当者（未割当は「担当未割当」）／事業所名（案件詳細へ）／住所（Googleマップ）／電話（押すと発信）／ステータス／**準備の状況**（見積：発行済・受注確定、出荷：依頼済・発送済、請求）／対面・オンライン／Googleカレンダーに追加 |
| 色 | ステータスの段階で色分け（受注確定〜伴走支援待ち＝これから、伴走支援実施済以降＝済み、確認中など＝要確認）。対面・オンラインはアイコンでも区別 |
| 絞り込み | **担当者**（「自分の予定だけ」を含む）・都道府県。ケアプー記録に無い担当者の絞り込みは、CRM では担当が多いので付ける |
| 件数 | 表示中の期間の担当者別の件数 |
| 更新 | onSnapshot なので、別の人が入力した予定もすぐ反映（自動更新ボタンは不要） |
| 権限 | 一覧と同じ（登録済み・有効な人。練習生は練習DBの予定を見る） |
| 入力 | カレンダー上ではしない（表示専用）。日付・時刻は案件詳細で入れる |

### 案件詳細の変更（時刻を入れられるようにする）
- 「訪問予定日」の横に **開始・終了の時刻** と **対面／オンライン** を足す（`cases.visitTimeFrom` / `visitTimeTo` / `visitFormat`）。
- 変更は今の訪問予定日と同じく、活動記録に「訪問予定を変更 → 10/28 15:00〜16:00（対面）」と残す。
- チェックリストの「当日」タブの日時は、**空欄のときだけ案件の値を初期表示する**（二重入力を減らす。上書きはしない）。

## 5. 第2段以降（第1段のあとに判断）
- ホーム（今日やること）に「今日の訪問 N件」のカードを出す。
- 毎朝の日次まとめ（Chat）に「今日の訪問」を載せる（担当ごと）。
- 訪問予定日を過ぎても「伴走支援実施済」になっていない案件に注意を出す（ケアプー記録の「伴走完了にしますか？」と同じ考え方）。
- 地図に今日の訪問先を出す（事業所の画面との連携）。

## 6. 進め方
1. `main` から作業ブランチを切る（今の `warehouse` ブランチの未コミットとは混ぜない）。
2. 日付の計算・絞り込み・並び順を純粋な関数にして `scripts/test-schedule.mjs` で確かめる（JST・週の始まり・月またぎ・時刻未定の並び）。
3. 画面を作る → `test-practice-mode.mjs` ほか既存テストを全部通す。
4. プレビューチャンネルで、実データ（今日の #29 ほのぼの様・#235/#302 アルファケア様など）を見て確認 → **リリース前チェック** → Codex レビュー → 本番へ昇格（直接デプロイしない）。
5. マニュアル（MANUAL.md・manual.html の「訪問予定日」の節）と、必要なら動画マニュアルを直す。

目安: 第1段で 1日程度（画面・案件詳細の時刻欄・テスト・プレビュー確認）。
