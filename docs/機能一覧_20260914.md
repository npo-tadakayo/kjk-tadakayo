# 介護情報基盤システム 機能一覧

## 1. この文書について

- **作成日**: 2026-09-14
- **根拠**: すべてコードを実読して作成（HANDOFF・記憶・口頭の申し送りは根拠にしていない）。読んだファイルは本文中に `ファイル名:行番号` または `関数名` で添えている。
- **対象**: NPO法人タダカヨ「介護情報基盤伴走支援事業（タダサポ＋）」の
  - 公開LP（`index.html`）
  - 見積もり・申し込みツール（`mitsumori.html`）
  - CRM管理画面（`admin/*.html` ・ `admin/js/*.js`）
  - 認定事業者ポータル（`admin/partner.html`）
  - 伴走支援承諾書 公開署名ページ（`admin/consent.html`）
  - Cloud Functions（`functions/index.js` ・ `functions/analytics.js` ・ `functions/estimate-pricing.js`）
- **更新の目安**: 画面・Functionsを追加/変更したとき、または半年に一度の棚卸し時に読み直して更新する。
- **書かないこと**: 利用者・事業所・担当者の実名やメールアドレス、Webhook URLやAPIキーの値（rule02準拠）。

## 2. 全体像

### 2.1 3つの入口

| 入口 | ファイル | 誰が使うか | ログイン |
|---|---|---|---|
| 公開LP | `index.html` | 一般の介護事業所（検索・広告・紹介で来訪） | 不要 |
| 見積もり・申し込みツール | `mitsumori.html` | LPから来た事業所、または直接案内された事業所 | 不要（URLのトークンで案件と紐付く） |
| CRM管理画面 | `admin/*.html`（`index.html`＝ログイン画面） | タダカヨの職員（伴走支援担当・経理・管理者） | 要（`@tadakayo.jp` のGoogleアカウント） |
| 認定事業者ポータル | `admin/partner.html` | タダサポ認定事業者（カードリーダーの発注者） | 要（Googleアカウント＋`partners`コレクションの許可リスト） |
| 伴走支援承諾書 署名ページ | `admin/consent.html` | 伴走支援を受ける事業所（CRMから送られたURLを開く） | 不要（トークンURLが鍵） |

### 2.2 データの流れ（1件の案件がたどる道）

| 段階 | 何が起きるか | 主な画面・処理 | できるデータ |
|---|---|---|---|
| ① 問い合わせ | 事業所がLPのフォームから送信、または見積もりツールを直接開く | `index.html` お問い合わせフォーム → Cloud Functions `webhookLpInquiry` | `cases`（新規・status=1）、`offices`、`activities` |
| ② 案件化 | 問い合わせ・見積もりのたびに事業所・案件が自動登録される（5分以内の重複問い合わせは無視、進行中の案件があれば追記） | `webhookLpInquiry` / `webhookMitsumori`（Cloud Functions） | `cases`、`offices` |
| ③ 見積もり | 事業所がプラン・台数を選び、見積書PDFを取得 | `mitsumori.html` → `webhookMitsumori` → `sendQuotePdf` | `quotes`（版管理） |
| ④ 申込 | 事業所が「この内容で申し込む」を確定 | `mitsumori.html` → `acceptQuote` | `cases.status=3`（受注確定）、`shipments`（出荷の下書き自動生成） |
| ⑤ 伴走支援 | タダカヨ職員が事前確認・当日・アフターの各工程をCRMで記録 | `case-detail.html`（各タブ）、`support-checklist.js` | `supportChecklists`、`sessions`、`activities` |
| ⑥ 出荷 | カードリーダーを事業所（または認定事業者）へ発送 | `supply.html?tab=shipments` | `shipments` |
| ⑦ 請求 | 請求書を発行し、経理へ報告 | `supply-print.html?type=invoice`、`reportInvoiceToAccounting` | `shipments.status=invoiced` |
| ⑧ 入金 | 入金を記録、過入金は他請求へ充当 | `supply.html` 入金モーダル | `shipments.payments[]` |
| ⑨ 領収証 | 入金済みの出荷に領収証を発行 | `supply-print.html?type=receipt` | `receipts/{shipmentId}` |
| ⑩ 助成金申請 | 事業所が介護情報基盤ポータルへ申請（タダカヨは書類準備を支援） | `case-detail.html` 申請情報タブ | `subsidyApplications` |
| ⑪ 完了・フォロー | 採択・入金確認、定着状況のフォロー | `case-detail.html` アフタータブ | `supportChecklists.after` |

**在庫の考え方（保管場所ごとの在庫管理）**: `products.stock`（合計）と`products.stockByLocation.{locationId}`（保管場所別）を両方持ち、在庫を動かす処理は必ず在庫更新関数を通す設計。保管場所は複数登録可能で、発地（都道府県）が滋賀県以外だとゆうパック送料表が滋賀発である旨の注意が出る。「郵送なし（手渡し・持参・現地設置）」の配送方法は送料0円だが在庫の出庫記録自体は通常どおり残る。

**在庫・発注・出荷・受注のステータス（コード上の値）**
- 発注（`purchaseOrders.status`）: `draft`（下書き）→`sent`（発注済）→`received`（入荷済）。`sent`→`draft`に戻す操作あり。
- 出荷（`shipments.status`）: `draft`（下書き・直送発注からの自動生成のみ）→`shipped`（発送済）→`invoiced`（請求済）→`paid`（入金済）。`canceled`という値も定義されているが、実際に遷移させる画面操作は見当たらない（詳細は§11）。
- 受注（`partnerOrders.status`）: `received`（受付済）／`confirmed`（受注確定）／`shipped`（出荷済）／`canceled`（キャンセル）。セレクトで自由に切替可能。
- 在庫増減理由（`inventoryMovements.reason`）: `manual_in/manual_out`（手動調整）、`stocktake_in/stocktake_out`（棚卸し調整）、`defect_in/defect_out`（不良・破損）、`location_assign`（未割当在庫の場所割当）、`po_received`（発注の入荷）、`shipment`（出荷登録・確定時の引落）、`shipment_edit`（出荷修正時の差分調整）、`shipment_canceled`（出荷削除時の戻し）。

## 9. 権限（役割）と見え方の違い

`admin/js/role.js`が全画面共通のゲート。ロールは`users`コレクションの`role`フィールドで管理し、**管理者（admin）／スタッフ（staff）／閲覧のみ（viewer）**の3種類（`admin/users.html`のUIにも明記）。

| ロール | できること |
|---|---|
| 管理者（admin） | 全機能に加えて、設定・ユーザー管理・料金/送料設定・認定事業者の登録編集・売上シミュレーター・案件の完全削除が可能 |
| スタッフ（staff） | 通常業務（案件対応・伴走支援記録・出荷/請求/入金の操作・見積もり対応）が可能。案件の統合も可能。設定・ユーザー管理・料金設定・認定事業者管理・シミュレーターへは入れない（`gateRole(...,{adminOnly:true})`で拒否） |
| 閲覧のみ（viewer） | 参照が中心。書き込み系のボタン（文言に「保存・登録・追加・削除・変更・記録・送信・確定・取り込・統合・調整・入荷・発行・報告・充当・返金・案内・作成・更新・戻す・停止・再開・対象外・修正」を含むもの）は自動的に無効化され押せない。検索・絞り込み・印刷・PDF・開く・戻る・ログアウト・コピー・表示は操作可能 |

**未登録・停止中のアカウント**: `users`に未登録、または`active:false`のアカウントはログインできず、専用の拒否画面（登録依頼の案内）が表示される（`role.js showAccessDenied`）。

**閲覧のみの実装方法**: `applyViewerMode()`がページ内の`button`・`a.btn`・`input[type=submit]`のテキストを正規表現で判定し、書き込み系のみ`disabled`＋半透明化。あとから描画される一覧・モーダルにも`MutationObserver`で継続して適用。画面最上部に「閲覧のみの権限でログインしています」という帯を常時表示。

**案件統合の権限差**: 完全削除は管理者のみ／統合（重複案件のマージ）は管理者・スタッフ（統合はデータが消えず対象外になるだけのため、削除より1段階ゆるい権限）。

**認定事業者・パートナーポータル**: `@tadakayo.jp`のロールとは別に、`partners`コレクションへの登録＋`active:true`が必要（`partner.html`）。
