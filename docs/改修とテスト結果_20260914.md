## 4. テストで見つけて直したもの（9件）

| # | 発見 | 対応 |
|---|---|---|
| 1 | 一括申込・一括見積もりで一部が失敗しても「成功」と返していた（Codex レビュー P1） | `partial`／`error` を返し、画面は受け付けた分と失敗した事業所名を分けて表示 |
| 2 | 重複時の応答 `groupId` が保存値とズレる | 既存版の groupId を返す |
| 3 | 申し込み済みの案件にも「見積もりを作る」が出る | 非表示＋サーバで拒否（改版は「内容を変更する」） |
| 4 | まとめ見積もりの兄弟案件が「重複の可能性」に出て統合を誘う | 同じグループは除外 |
| 5 | 見積書（CRM版）の右上ラベルが折れる・「お客様ご負担額」の表記 | `nowrap`・「事業所さまご負担額（自己負担）」 |
| 6 | 電話・URL の入力欄が細い | 共通スタイルを適用 |
| 7 | 保管場所の在庫合計が更新されない | 購読時に再描画 |
| 8 | 撮影用サンプルの `receiptIssuedAt` を timestamp で書くと一覧が崩れる | 実装は文字列日付。サンプルの型を合わせた（実装は変更なし） |
| 9 | 「メール本文の桁区切りが無い」と一度判断したが、Gmail の要約表示がカンマを落としていただけだった | 本文で確認し訂正。金額整形は Intl 非依存の `fmtNum()` に統一（害なし） |

## 5. 個人情報・外部送信の観点（詳細は同日の PMS 報告）

- 外部へ出る通信は**増えていません**（Formspree は 9/9 に停止済み。zipcloud・Clarity・GA4 は従来どおりで、事務局の判断待ち）。
- 本番通し確認のメール宛先はすべて開発担当自身。事業所名は【削除予定テスト】。テストデータ（案件11件・見積10件・出荷8件・事業所10件・記録・トークン・PDF）は**すべて削除し 0件を確認**。
- 動画の画面写真は**サンプルデータ**（Firestore に直接作成し撮影後に削除）で撮影。実在の事業所名・担当者名・メールは映っていません（職員名と、LP に公開している認定事業者名は可）。
