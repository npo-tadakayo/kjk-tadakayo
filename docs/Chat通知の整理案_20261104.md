# Chat 通知の整理案：投稿種別ごと・地域ごと（2026-11-04）

依頼元：次田さん（「出荷依頼が多く、案件決定の連絡もスペースに多い。投稿種別ごと・地域ごとに、適切な管理方法を提案してほしい」）。状態：**提案のみ。コード・設定は変えていない。**

## 1. いまの状況（実測）

## 2. 見えてきた問題
1. **「自分に関係ない通知」が大半**。全員が入るスペースに、本人宛の通知（担当決定・日次の担当者別）が約250件/2週間流れる。人の会話が埋もれ、肝心の通知（自分の担当・倉庫の出荷指示）も見落とす。
2. **人の会話と機械の通知が同じスペース**にあるため、通知をミュートできない。
3. **地域で分けたくても、地域がわからない案件が31%**。地域別にルーティングしても、113件は行き先が決まらない。
4. **出荷の情報が二重**：OP の長文通知と、倉庫の画面（一覧タブ）が同じ内容を持つ。

## 3. 原則（提案）
1. **Chat は「知らせる」道具、CRM は「管理する」道具。** 一覧・絞り込み・集計・チェックは CRM に寄せ、Chat は「新着の合図」を短く。
2. **人が話すスペースと、機械が知らせるスペースを分ける。** 通知スペースは、各自がミュートや通知の強さを決められる。
3. **受け手ごとに分ける。** ①自分だけ（担当者本人）②チーム（営業・事務）③倉庫 ④全員。全員向けは日次の1通だけにする。
4. **地域は、まず「見出し」と「CRMの絞り込み」で扱い、スペースの分割は件数が多い地域だけ。**（理由は §5）

## 4. 投稿種別ごとの行き先（案）
| 種別 | いま | 提案 |
|---|---|---|
| 人の会話・相談 | TM | **TM はこれだけにする**（人の会話の場） |
| 📦 出荷指示 | OP（長文・12項目） | **OP のまま。**文面を短く（出荷番号・地域・台数・依頼者＋倉庫の画面へのリンク）。会話はスレッド内（今のまま）。出荷元が増えたら、出荷元ごとのスペースに分ける（今は1か所なので不要） |
| 👤 担当営業が決まりました | TM（全員） | **「案件の通知」専用スペース（自動）**へ。担当者には @メンション。見たい人だけ入る・ミュート可 |
| ✍️ 承諾書の署名／🎉 お申し込み／📞 電話の申込／🛒📥 LP問い合わせ | TM（全員） | **「新規・受注の通知」専用スペース（自動）**へ（営業・事務・倉庫が入る） |
| 🗓 日次フォローアップ（担当者別・@メンション） | TM（人数分） | **やめる。**担当者別の内容は CRM の「ホーム（今日やること）」で見られる。希望者だけ、DM かメールで受け取る（別途） |
| 🗓 日次フォローアップ（全体） | TM | **1通のまま。**投稿先は「案件の通知」スペース（地域別に分ける案は §5） |
| 請求・経理 | accounting（既存） | 変更なし |

→ 期待される効果（実測の割合から）：TM の自動投稿380件/2週間のうち、**約360件（95%）が TM から消える**。TM は人の会話中心に戻る。

## 5. 地域ごとの扱い
- **スペースを地域で分けると、「地域 × 種別」で管理対象が増える**（例：7エリア×3種別＝21スペース）。担当者の入れ替わり・追加のたびに保守が要る。
- 件数の分布は偏っている（沖縄68・宮崎31・大阪27・京都24・静岡20・山梨19、ほかは10件未満）。**分けて効果が大きいのは沖縄・宮崎くらい**。
- **先にやること：地域不明の113件（31%）をなくす。**住所（都道府県・市）の入力を必須にする／既存の113件を補完する。これをしないと、地域別ルーティングは行き先が決まらない。
- 提案：
  1. **第1段階**：スペースは種別だけで分ける（§4）。地域は、通知の見出し（いま入っている【都道府県 市】）とメンションで絞る。見たい地域は、CRM の案件一覧の「地域」で絞る。
  2. **第2段階**：件数が多い地域（沖縄・宮崎など）だけ、**地域別の案件通知スペース**を作り、通知の行き先を「都道府県→スペース」の対応表で決める。それ以外は全国の通知スペース。
  3. 対応表は CRM の設定画面で管理（既存の「投稿先の設定」を、種別×地域に拡張）。

## 6. 実現の方法（CRM 側）
- 既存の仕組み（`WEBHOOK_FIELDS`・設定画面）を拡張：投稿先の種類を `crm` 1つから、`assign`（担当決定）・`sales`（新規・受注）・`digest`（日次）などに増やし、種別ごとに URL を持つ。**種別の分離は小改修（約1日）。**
- 日次の担当者別投稿を止める：日次バッチの出力（`Flow.planDailyPosts`）から担当者別の投稿を外す。小改修。
- 出荷指示の文面を短くする：`shipmentChatMessage`。小改修（倉庫の画面で詳細が見られるため）。
- 地域別ルーティング（第2段階）：「都道府県→投稿先」の対応表と、`officeRegionLabel` の地域判定を使う。**地域データの整備が先**。
- 本番へは、rule05 どおり（Functions は `--only` で関数名を列挙・画面は Preview→verify→昇格）。通知先を変える前に、`testChatNotify`（テスト通知）で新しいスペースへの到達を確認する。
