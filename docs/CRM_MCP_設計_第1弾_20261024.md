# タダカヨCRM の MCP（Claude から CRM を使う）設計書 — 第1弾（2026-10-24・案）

> **この文書の目的**: システムの管理権限を持つ方に、作る前に確かめて了解をいただくための設計書。
> 何ができるか・何ができないか・どう守るかを先に決める。**未実装**。

## 1. なぜ作るか

- 介護情報基盤 CRM の入力・記録の多くを、次田さんが Claude（Claude Code）経由で行っている（案件を探す・対応記録を書く・担当とステータスを変える など）。
- 他のメンバー（まず **藤田さん・蜂須賀さん**）にも同じことをできるようにしたい。
- ただし、**今の次田さんの仕組みはそのまま配れない**。次田さんの Google Cloud の権限でデータベースを直接読み書きしており、**CRM の権限ルール（閲覧のみ・練習生・倉庫）を通らない**。同じものを配ると、全員が全データを読み書きできてしまう。

→ **CRM の権限ルールを必ず通る「タダカヨCRM 専用の MCP サーバー」をクラウドに置き、Claude（Team プラン）のコネクタとしてつなぐ。**

## 2. 全体の形

```
メンバーの Claude（Team プラン・デスクトップ／Web）
   └─ コネクタ「タダカヨCRM」（MCP サーバー・Cloud Run・プロジェクト kjk-tadakayo）
        1. 本人確認   … Google ログイン（@tadakayo.jp だけ）
        2. 権限確認   … CRM の利用者登録（users）とロールを毎回確かめる（画面・Functions と同じ判定）
        3. 道具（ツール） … 第1弾は「読む」と「記録する」だけ
        4. 記録      … 誰が・いつ・どの道具で・どの案件に、を残す（中身の個人情報は残さない）
```

- メンバー側の準備は **Claude にコネクタを1つ足して、Google でログインするだけ**。プログラムの導入は不要。
- 前例: 279 の「レジェンドケアマネ MCP」（Cloud Run）。ただしあちらは共通の鍵（APIキー）で、**誰が使ったかを区別しない**。今回は**一人ひとりのログインで区別する**点が違う。

## 3. 第1弾でできること（ツール一覧）

| ツール | 内容 | 読み／書き | 使える人 |
|---|---|---|---|
| `find_cases` | 案件を探す（事業所名・法人名・地域・ステータス・担当で） | 読む | 管理者・スタッフ・閲覧のみ |
| `my_cases` | 自分が担当の案件（ステータス別・初期連絡の超過など） | 読む | 同上 |
| `get_case` | 案件の詳細（事業所・担当者の連絡先・ステータス・直近の対応記録・見積もり・出荷の要約） | 読む | 同上 |
| `list_activities` | 案件の対応記録の一覧 | 読む | 同上 |
| `find_offices` | 事業所を探す | 読む | 同上 |
| `add_activity` | 対応記録を書く（電話・メール・訪問・メモ など） | **書く** | 管理者・スタッフ |
| `set_status` | ステータスを変える（変更履歴の記録つき・画面と同じ動き） | **書く** | 管理者・スタッフ |
| `assign_case` | 担当営業を決める・変える（担当通知が Chat に出る・画面と同じ） | **書く** | 管理者・スタッフ |
| `set_visit_date` | 訪問予定日を入れる | **書く** | 管理者・スタッフ |

**第1弾ではやらないこと**: メールの送信・Chat への投稿・見積もりの作成と送付・出荷・請求・入金・案件や事業所の削除・統合・利用者管理・設定の変更。
（送ること・お金に関わること・消すことは、画面で人が確かめて行う。第2弾以降で「下書きまで」を検討）

- 練習生（新人）と倉庫の担当は使えない（画面と同じ）。
- 書くツールは、CRM に「**〇〇さん（Claude 経由）**」と記録する。画面で書いたものと区別できる。
- 書くツールは、Claude 側でも実行前に確認が出る設定にする（§6）。

## 4. 守り方

### 4.1 本人確認と権限
- Google ログインで **@tadakayo.jp かつメール確認済み** の人だけ。
- ツールを呼ぶたびに CRM の `users/{email}` を読み、**有効か・ロールは何か**を確かめる。判定は Functions の `Flow.roleAllows`（画面・既存の Callable と同じ部品）をそのまま使う。
- CRM の利用者から外す・無効にすると、**次の呼び出しから使えなくなる**（Claude 側の設定を待たない）。

### 4.2 データの出し方（必要な分だけ）
- 一覧（`find_cases` など）は、事業所名・ステータス・担当・日付まで。**担当者の電話・メールは出さない**。
- 連絡先は `get_case`（1件の詳細）のときだけ出す。
- 金額は第1弾では「合計」だけ（明細・振込情報は出さない）。
- 一度に返す件数に上限（例: 50件）。CRM 全件の書き出しはできない作り。

### 4.3 記録（監査）
- 新しい記録 `mcpAudit`: 日時・メール・ツール名・案件番号・成功／失敗。**検索語や本文などの中身は残さない**（個人情報を二重に持たないため）。
- 書く操作は、CRM の対応記録・ステータス履歴にも、画面と同じ形で残る。

### 4.4 サーバー
- Cloud Run（kjk-tadakayo・東京）。専用のサービスアカウントを作り、権限は **Firestore の読み書きだけ**。
- 鍵・トークンの署名鍵は Secret Manager。コードに書かない。
- 失敗・拒否の回数をログで見られるようにする。

## 5. 個人情報の扱い（了解をいただきたい点の中心）

- **CRM に入っているのは「事業所」の情報**（事業所名・所在地・担当者の氏名と連絡先・やり取りの記録）。**介護を受ける方（利用者・被保険者）の情報を入れる欄は無い**。自由記入の欄（伴走支援の記録など）には「利用者（被保険者）の個人情報は書かないでください」と画面で案内している（`admin/js/support-checklist.js`）。ただし自由記入なので、**書かれていないことを機械では保証できない** → MCP の `get_case`／`list_activities` は対応記録の本文を返すので、この案内の徹底が前提になる。
- それでも、担当者の氏名・電話・メールは個人情報にあたる。タダカヨの **AI利用ガイドライン（ドラフト）** は「特定個人を識別できる情報は AI に入力しない」を原則にしている。
  → このMCPを使うと、Claude が事業所の担当者の連絡先を読む。**ガイドラインに例外を1つ足す必要がある**:
  > 「法人として契約した AI サービス（Claude Team プラン）で、タダカヨが用意した接続（CRM の MCP）を通す場合に限り、業務上必要な範囲で事業所の担当者の連絡先を扱ってよい。利用者（介護を受ける方）の情報は扱わない。」
- Claude Team プランのデータの扱い（学習に使われるか・保存期間）は §7 の調査結果を添える。
- 使う人は **Team プランの席を持つ人だけ**（個人のプランでは使わない）。

## 6. Claude 側の設定（Team プラン）

- **コネクタを足せるのは Team の Owner（管理者）だけ**。組織の設定 → コネクタ → 追加 → カスタム で、URL を入れる。メンバーは自分では足せない。
- メンバーは「カスタマイズ → コネクタ」で「タダカヨCRM」の **接続** を押し、**自分の Google アカウント（@tadakayo.jp）でログイン**する。一人ひとりが別のログイン＝誰が使ったか区別できる。
- **書くツールは実行前に確認が出る**ようにする: ツールに「読むだけ（readOnlyHint）」の印を付け、書くツールには付けない。Owner は組織全体で「書くツールは毎回確認」「使わせない」を決められる（メンバーは上書きできない）。※Team で Enterprise と同じ細かさで決められるかは要確認。
- 「リサーチ」モードではツールが確認なしで動くことがあるため、案内で注意する（書くツールは通常の会話で使う）。
- 認証の設定は追加後に変えられない（変えるときは追加し直し、メンバーは接続し直し）。

## 7. 調査結果（Claude Team のコネクタ・2026-10-24 時点・出典つき）

| 項目 | 分かったこと | 出典 |
|---|---|---|
| 追加できる人 | Team は Owner／Primary Owner だけ。メンバーは接続して個別にログイン | support.claude.com/en/articles/11175166 |
| つなぎ方 | Streamable HTTP（推奨）。https 必須 | claude.com/docs/connectors/building |
| 呼び出し元 | **Anthropic のクラウドからサーバーを呼ぶ**（メンバーのパソコンからではない）。インターネットから届く必要あり。絞るなら Anthropic の送信元 `160.79.104.0/21` | claude.com/docs/connectors/building/authentication.md・platform.claude.com/docs/en/api/ip-addresses |
| ログイン方式 | OAuth（PKCE 必須）。**事前に発行したクライアントIDを登録する方式**が使える（自動登録は必須ではない）。戻り先 `https://claude.ai/api/mcp/auth_callback` | 同上 |
| Google を使うには | Google 自体は Claude のログイン相手（認可サーバー）になれない → **MCP サーバーが小さな認可サーバーを持ち、ログインは Google（tadakayo.jp に限定）に任せ、自前の短い期限のトークンを出す**（調査担当の推論。Anthropic の文書に禁止の記載なし） | 同上 |
| 実行前の確認 | 既定で確認が出る。readOnlyHint の付いたツールは確認なしで動けて、destructiveHint は必ず確認 | claude.com/docs/connectors/building/review-criteria.md |
| データの扱い | Team など法人向けは、**入力・出力を学習に使わない**（既定）。例外は 👍👎 などのフィードバックを送ったとき（最長5年保存）→ **組織の設定でメンバーのフィードバックを切っておく** | privacy.claude.com/en/articles/7996868 |
| 上限 | 1回の結果は約15万字・240秒まで。ツール名は64文字以内 | claude.com/docs/connectors/building |
| 未確認 | 法人向けの会話の保存期間／Team での細かい権限設定の範囲 | — |

**この結果から設計に入れること**: ①サーバーはインターネットから届く Cloud Run（ログインと CRM の権限確認で守る。必要なら Anthropic の送信元だけ通す）②認可サーバーを内蔵し、Google ログイン（hd=tadakayo.jp・メール確認済み）を必須にする ③読むツールに readOnlyHint を付け、書くツールは毎回確認 ④Team の組織設定でフィードバック送信を切る。
