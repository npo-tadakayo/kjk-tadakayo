## 3. 請求書: 都度の通知をやめ、PDF は毎回保管する

- 設定（管理者）に **「請求ごとに経理へ通知する」**（`accountingNotifyEach`・既定 OFF）を足す。OFF の間は「請求済にする」の確認画面の「経理へ報告する」を初期 OFF・非表示にし、メールも Chat も送らない。
- **請求書 PDF の保存を、通知と切り離す。**「請求済にする」のたびに、ブラウザで作った PDF を Storage に保存する（今は報告 ON のときだけ）。これは**「事業所へ送った版」の記録**で、上書きせず版ごとに残す（`invoices/{shipmentId}/sent/{INV番号}_{保存日時}.pdf`・`invoiceSentPdfs[]` に日時と保存者）。**Drive の控えには使わない**（中身は請求後に変わることがあるため・§5.2）。
- 出荷の行と請求書の画面に **「保存した請求書PDF」** のリンクを出す（職員のみ。Storage のルールは今のまま）。
- ※ Chat のリンクに使っているダウンロードトークン付き URL は誰でも開けるため、通知をやめたあとは新しく発行しない。

## 4. 月ごとの売上一覧（スプレッドシート）

- **計上の基準日は請求書の発行日（`invoicedAt`）**（10/30 次田さん決定・§8-1）。請求済・入金済が対象、キャンセルは除く。
- 列（1行＝1出荷・請求書）:
  請求書番号／発行日／支払期限／請求先（法人名）／事業所名／案件番号／区分（訪問・通所系／居住・入所系／その他）／カードリーダー台数／金額（税込）／うち助成金充当／入金額／入金日／未収額／状態（請求済・入金済）／領収証番号／担当
- 2つの出し方:
  1. **画面から**: 供給管理に「月次の売上」タブ。月を選ぶと一覧と合計（件数・金額・入金済・未収）を表示し、CSV をダウンロード（いつでも・誰でも同じ結果）。
  2. **毎月自動で**: 毎月1日 9:00（JST）に前月分を、§5 で設定した Drive フォルダへ **Google スプレッドシートとして**作る（`月次売上_2026-10`）。作ったら経理の Chat に「前月分を置きました」とリンク1本だけ投稿（都度の通知はしない）。
- 月の途中で入金が入っても、表は「その月に請求したもの」を一覧にし、入金の列で追えるようにする。

## 5. Google ドライブへの保存（保存場所は設定で変えられる）

### 5.1 設定（管理者だけ・設定画面「経理」）
| 項目 | 内容 |
|---|---|
| 保存先フォルダ | Drive のフォルダ URL を貼る（ID を取り出して保存 `accountingDriveFolderId`）。**いつでも差し替え可能** |
| 月ごとのフォルダを作る | ON なら `2026-10` のような子フォルダを自動で作って入れる（既定 ON） |
| 有効／停止 | 停止中は保存しない（あとで「まとめて保存」できる） |
| 接続テスト | ボタンで、フォルダにテストファイルを置いて消す。権限が無ければ理由を表示 |

- 保存先を変えても、**すでに置いたファイルは動かさない**（以後の分だけ新しい場所へ）。設定の変更は履歴に残す（誰が・いつ・どこから→どこへ）。

### 5.2 領収証を発行したときに、請求書と領収証の控えをまとめて置く（10/30 次田さん決定）
請求書の中身は、請求したあとで変わることがある（例: 法人名を正式名に直した・台数を直した）。そのため Drive の控えは、**入金が確定して領収証を発行した時点の最新のデータ**で作る。
- 領収証の画面で「この内容で発行済にする」を押したとき、ブラウザで**請求書と領収証の PDF をその時点のデータで作り直し**、callable（例 `archiveBillingDocs`）に渡す。
- Functions が2つを Storage `archive/{shipmentId}/` に保存し、Drive の保存先（月ごとの子フォルダ＝**入金日の月**）に置く。
  - 請求書: `{入金日YYYYMMDD}_{INV番号}_{請求先}_{金額}円_請求書.pdf`
  - 領収証: `{入金日YYYYMMDD}_{RCPT番号}_{請求先}_{金額}円_領収証.pdf`
- 出荷に `driveArchivedAt`・`driveFiles[]`（種類・fileId・名前）・`driveFolderId` を残す。失敗したら `driveArchiveError` を残し、出荷の行に「Driveへ保存（再試行）」ボタン。再試行も、その時点のデータで作り直す。
- **入金済でも領収証を発行していない出荷は、Drive に置かない。** 出荷の行と未処理の一覧に「控え未保存」を出して気づけるようにする。
- 領収証を再発行した（内容を直した）ときは、Drive の控えも新しいものに差し替え、古いものは同じフォルダの `_旧版/` へ移す（消さない）。
- 請求したときに保存した PDF（§3）は「送った版」の記録として Storage に残し、Drive には置かない。

### 5.3 権限のしくみ
- 新しいサービスアカウント `fn-drive-sa`（Drive の書き込みだけ）を作り、**保存先のフォルダ（共有ドライブ推奨）に「コンテンツ管理者」で招待**する。ドメイン全体の委任は使わない。
- 保存先を変えるときは、新しいフォルダにもこのアカウントを招待する（設定画面に手順とアカウントのメールを表示し、接続テストで確かめる）。
- 置くのは事業所・法人の請求書だけ。利用者の情報は入らない。

## 6. 棚卸し（11月以降・締めごとに）

- 供給管理に **「棚卸し」** を追加。締め日と保管場所を選び、品番ごとに**実際の数を入力** → CRM の数との差を表示 → 「確定」で差分を在庫調整（理由＝棚卸し）として記録。
- 確定時に **`stocktakes/{締め日}_{保管場所}`** にスナップショット（CRM の数・実数・差・入力者・確定日時）を残す＝締め日の在庫がいつでも見られる。
- 確定した表を §5 の Drive に `在庫締め_2026-11-30_ロジスティックセンター` として保存し、経理へは月次と同じく1本だけ連絡。

## 10. 入金の確認の自動化（PayPay銀行・freee会計との連携・2026-10-30 案）

### 10.1 今わかっていること（調査 10/30・公式サイトほか）
| 対象 | わかったこと |
|---|---|
| PayPay銀行 明細CSV | Web画面から CSV を取得できる（1回5,000件・過去5年）。**CRMにはすでに銀行CSVの取り込み（`bank-import.js`）がある** |
| PayPay銀行 API | 法人向け「API連携（残高・明細）」はあるが、契約と審査が要り、費用は問い合わせ。直接使うには個別相談 |
| PayPay銀行 ワンタイム口座 | 取引先ごとに振込専用の仮想口座を発行し、入金を API で即時通知。最短約6週間・審査・自社開発あり。費用の表示は 200,000円・10,000円（名称は読み取れず）、出金1件2円 |
| PayPay銀行 振込専用口座 | 請求書ごとに口座番号を分けられる。**新規申込は停止中**との記載（要確認） |
| freee会計 口座同期 | PayPay銀行の口座を同期できる（リアルタイムではない。1日数回と思われる） |
| freee API | 取引（売掛）の作成 `POST /api/1/deals`、決済の登録 `POST /api/1/deals/{id}/payments`、明細の読み取り `GET /api/1/wallet_txns` が使える。OAuth2（アクセス6時間・リフレッシュ90日・1回限り） |
| freee 明細の消込API | 2026年10月から**認定アドバイザー向けに順次提供**（一般の事業所への開放は未定） |
| freee 自動登録ルール | 振込名義などの条件で、入金明細を未決済の売掛取引に自動で結び付けられる（プランによる） |
| 振込名義 | **実データでは、請求書番号の数字を名義の頭に入れて振り込む事業所が多い**（例「振込 ００７９ ド）キヤンバス」「０１１２ＷアンドＷ…」「００５５ イ）トウシンカイ」）。請求書の振込案内に番号を書いているため |

### 10.2 方針（段階的に進める）
**段1: いまの CSV 取り込みを「ほぼ自動」にする（銀行の新しい契約なし）**
- 振込名義の頭の数字（全角も）を請求書番号として読み、**番号＋金額が一致すれば「確定してよい候補」**として先頭に出す。合算（例「００７４００７５」＝2件分）にも対応する。
- 番号が無いときは、法人名・事業所名のカナ（「ユ．アイカイゴセンタ－」→愛介護センター 等）と金額で候補を出す。名義と法人名の対応は、一度確定したら覚えておく（次回から自動で候補）。
- 確定は今までどおり人が押す（1クリック）。確定すると、入金記録・領収証の発行（入金日）・入金消込台帳への反映までを一度に行う。
- 請求書の振込案内に「お振込名義の前に請求書番号（4桁）を入れてください」をはっきり書く（すでに入れている事業所が多いので、確実にする）。

**段2: freee会計とつなぐ（会計の正本に残す）**
- 請求済にしたとき、CRM から freee に**売掛の取引**（取引先＝法人・金額・発生日＝請求書の発行日・管理番号＝INV番号）を作る。CRM の請求書が正本のまま、freee には取引だけを送る。
- 入金を確定したとき、freee の取引に**決済（入金日・PayPay銀行の口座）**を登録する。
- freee が PayPay銀行の明細を同期しているので、段1の CSV 取り込みを、**freee の明細（`wallet_txns`）を CRM が1日数回読み取る形**に置き換える。手で CSV を落とす作業がなくなる。
- freee の明細の消込 API が一般の事業所に開放されたら、決済の登録を「明細との紐付け」に切り替える。

**段3（必要になったら）: PayPay銀行のワンタイム口座**
- 件数がさらに増えて、名義の揺れや合算で手間がかかるようになったら検討する。費用と開発期間がかかるので、今は見送る。

### 10.3 必要な準備
- freee: **タダカヨの事業所**で API アプリを登録（OAuth）。リフレッシュトークンは Secret Manager（タダカヨ GCP）に保存し、使うたびに保存し直す。**今このパソコンの freee の接続は株式会社279の事業所で、認証も切れている**ため、タダカヨの管理者アカウントでつなぎ直す必要がある（次田さんの操作）
- freee: PayPay銀行の口座が同期されているか、自動登録ルールが使えるプランかを確認
- freee: 取引先（法人）と CRM の法人の対応表を作る（初回は CRM から一括で作る）
- 勘定科目（売上高の補助科目・売掛金）と、助成金の扱い（事業所からの入金＝売上）を経理の田中さんと確認

### 10.4 決めてほしいこと
1. 段1（CSV取り込みの自動候補）から始めてよいか
2. freee とつなぐ（段2）か。つなぐ場合、取引の勘定科目・品目を経理と決める
3. 振込名義に請求書番号を入れてもらう案内を、請求書と振込案内に入れるか
