# 【PMS報告】介護情報基盤 CRM／LP 9/12〜14 改修に伴う個人情報の取扱いの変更点

> 2026-09-14 ／ 作成: 開発担当（次田）／ 宛先: 部門保護管理者（蜂須賀さん）・PMS事務局
> **この文書は開発側の点検結果です。規程上の位置づけは事務局のご判断をお願いします。**
> 前回報告（2026-09-08「LPの問い合わせフォームが外部サービスにも個人情報を送っていた件」）の続報を §5 に含みます。

---

## 1. 要旨（3行）

1. 9/12〜14 の改修で、**新たに取得する個人情報はありません**。増えたのは「ご希望」（相談／見積書／申込の3択＝個人情報ではない区分値）と、同一法人の**複数事業所を1回で入力できる仕組み**（事業所の情報が事業所数ぶん登録される）です。
2. **外部への送信は増えていません**。郵便番号の自動入力（zipcloud）は従来どおりですが、見積もりツールで事業所を追加するたびに同じ照会が走るようになりました。
3. テスト・動画撮影では**本番環境を使いましたが、実在の事業所の情報は使わず**、作成したテストデータはすべて削除しました（§4）。

---

## 2. 取り扱う情報の変更点

| 項目 | 変更 | 個人情報か | 保存先・期間 |
|---|---|---|---|
| ご希望（`inquiryIntent`） | LP問い合わせフォームの必須3択を案件に保存。Chat 通知にも1行明記 | いいえ（区分値） | Firestore `cases`・案件と同じ |
| 複数事業所のまとめ見積もり | 法人名・担当者名・電話・メールは法人で共通、事業所ごとに名称・住所・電話・URL・構成を保存。**事業所ごとに案件と見積書ができ**、グループID で束ねる | 事業所の担当者名・電話・メール（従来と同じ項目） | Firestore `cases`/`offices`/`quotes`（既存と同じ） |
| スタッフが見積もりを作る | CRM から見積もりを作成。作成者として**職員のメールアドレス**を保存（`createdBy`） | 職員の業務メール | Firestore `quotes` |
| 見積書PDFの保存・送付 | CRM で見積書を PDF 化し Storage に保存、事業所へメール添付 | 事業所の担当者名・連絡先を含む書面 | Storage `quotes/{案件}/`（従来の見積もりツールと同じ場所・同じ経路） |
| 一括申込の届け先 | 「各事業所の住所へ」または「1か所へまとめる」。届け先の担当者名・電話を出荷下書きに保存 | はい（従来と同じ項目） | Firestore `shipments` |
| 案件一覧の CSV | 「ご希望」列を追加 | 既存の CSV に区分値が1列増えるのみ | 職員が手元に保存 |

**画面の見え方**: 案件一覧・案件詳細で「ご希望」が見えるのは、従来どおり **@tadakayo.jp でログインした職員のみ**です。

## 3. 外部への送信（今回の改修での増減）

| 送信先 | 内容 | 今回の変化 | 状態 |
|---|---|---|---|
| Google Cloud（Firestore／Storage／Functions・asia-northeast1） | 案件・見積もり・PDF・メール送信 | 送る項目は増えず。件数は事業所数ぶん増える | 従来どおり（委託先） |
| Gmail API（kjk-staff@tadakayo.jp から送信） | 見積書・申込確認・改版メール | 複数事業所分を**1通にまとめて**送る形が増えた（宛先は同じ担当者） | 従来どおり |
| Google Chat（社内スペース） | 問い合わせ・申込の通知 | 「ご希望」を明記。まとめ見積もりは**グループで1通** | 従来どおり（社内） |
| **zipcloud**（郵便番号→住所） | 入力した郵便番号（閲覧者の IP が先方へ） | **見積もりツールで事業所を追加するごとに照会が増える**。送る内容は郵便番号のみで変化なし | 前回報告の**回答待ち**（§5） |
| Microsoft Clarity／GA4 | 閲覧行動 | 変化なし | 前回報告の**回答待ち**（§5） |
| Formspree | — | — | **9/9 に送信停止済み**。残存データの削除依頼が未了（§5） |

## 4. テスト・撮影における個人情報の扱い

| 場面 | 何をしたか | 個人情報の扱い |
|---|---|---|
| 本番通し確認（9/14・8経路） | 本番の Functions と本番／プレビューの画面で、問い合わせ→見積もり→申込→CRM 操作を実施 | 事業所名は「【削除予定テスト】…」、担当者は「次田テスト」、**メール宛先は開発担当自身**。実在の事業所・個人は使っていない |
| 通し確認で本番に作られたデータ | 案件 #157〜166（11件）、見積 EST-2026-0023〜0032、出荷 SH-2026-0019〜0026、事業所10件、記録、引き継ぎトークン、見積書PDF | **すべて削除し、残存 0件を照会で確認**（案件・見積・出荷・事業所・Storage）。番号は消費される |
| 通知 | 社内 Chat（介護情報基盤スペース）にテストの申込通知・問い合わせ通知が流れた | 実在情報なし。「テストなので無視してよい」旨を周知する |
| 動画マニュアルの画面写真（33枚） | 本番 CRM にサンプルの案件・見積・出荷・事業所（#9008〜9011）を **Firestore に直接作成**（Functions を通さないため通知・メールは発生しない）して撮影 | 撮影後に**全件削除**。写真に実在の事業所名・担当者名・メールが写っていないことを目視確認。写っているのは職員名（発注者・担当）と、LP に公開している認定事業者名のみ |
| 一覧画面の撮影 | 検索で「サンプル」に絞り、サンプル行だけが表示される状態で撮影 | 実データの行は写っていない（撮影前に件数と行の内容を確認） |
| 撮影の残り | 撮影用データはすべて削除済み。写真は `06_介護情報基盤事業/…/素材/shots/` と共有ドライブの動画に含まれる | サンプルデータのみ |
